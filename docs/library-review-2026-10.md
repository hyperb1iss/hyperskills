# Hyperskills Review: October 2026

Version 3.13.0 contained 14 skills. This review covered every entrypoint, the installed state on one machine, and the vendor guidance published since the [September 2026 audit](library-review-2026-09.md). A Claude Fable 5.1 coordinator ran it with Opus workers for the per-skill edits; the coordinator read every rewrite against a per-skill keep list, and a second model family reviewed the combined diff before merge.

The central finding is a split the library had not named. Anthropic's skill-creator guidance (March 2026) separates capability-uplift skills, which newer models absorb over time, from encoded-preference skills, which last. Five process skills (brainstorm, plan, research, implement, orchestrate) are the first kind: in the coordinator's reading, about half of each described behavior a current frontier model performs unprompted, and they activate on most tasks. The domain and mechanics skills are the second kind and kept their structure.

## Research That Changed the Design

Anthropic's [Opus 5 prompting guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5) says to remove explicit verification instructions such as "use a subagent to verify" because they cause over-verification on that model. Its [Fable 5 guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5) says separate, fresh-context verifier subagents tend to outperform self-critique on long runs, and that skills written for prior models are often too prescriptive. Both were read at the source on 2026-10-27. The library honors both by trigger rather than choosing one.

[arXiv 2606.05976](https://arxiv.org/abs/2606.05976) (June 2026) reports near-zero correction when a byte-identical error sits in the model's own reasoning and a 23 to 93 point rise when the same error arrives as a user, tool, or memory message. That is the mechanism behind requiring the verdict to arrive as a separate dispatch.

[arXiv 2607.27030](https://arxiv.org/abs/2607.27030) (July 2026) found one pass from each of four model families and four passes of the best single model located nearly the same number of vulnerabilities, with 62 percent of hits appearing in only one to three of four identical passes; the authors call the analysis exploratory. [arXiv 2506.07962](https://arxiv.org/abs/2506.07962) (ICML 2025) measured about 60 percent agreement between two models when both are wrong. Together they support treating repeat passes as diversity and agreement as a prioritization signal only.

[arXiv 2609.28090](https://arxiv.org/abs/2609.28090) (2026) reports that a reviewer prompt stating the code may be clean cut false-positive findings from 20.8 percent to zero on a clean-control benchmark. The Opus 5 guide separately warns that "be conservative" instructions reduce recall. The review skills now ask for every finding, say the code may be clean, and filter in a separate pass.

Anthropic's [skill-creator post](https://claude.com/blog/improving-skill-creator-test-measure-and-refine-agent-skills) (March 2026) supplied the uplift-versus-preference frame. [SkillsBench](https://arxiv.org/abs/2602.12670) (February 2026) measured curated skills at about 16 points overall but only 4.5 in software engineering, with 16 of 84 tasks regressing, and found focused skills beat comprehensive documents. A [progressive-disclosure comparison](https://arxiv.org/abs/2606.11543) (June 2026) found 4.1 percent more passing runs than one flat file with the same content. None of these evaluated this library; they support compressing process skills and keeping conditional detail in references.

The [Claude Code skills documentation](https://code.claude.com/docs/en/skills) states that on compaction each invoked skill is re-attached with its first 5,000 tokens inside a 25,000-token combined budget. By word count (the largest entrypoint is about 2,550 words) every entrypoint here sits well under that. The same page lists frontmatter fields beyond the Agent Skills specification; the [specification](https://agentskills.io/specification) was donated to the Agentic AI Foundation on 2026-10-22 with the format unchanged, and the same Claude Code page states that claude.ai uploads, the Skills API, and the packaging script reject fields outside the specification, so the library stays on the specification's fields.

## Verification and Limits

Validation completed during the review (receipts: the CI runs and review thread on pull request #11):

- `make check` and `make test` pass on the merged branch: manifests, parsed YAML, bundled references, the validator suite, the prose scanner regression suite, the observable review runner, and the demo-reel scripts.
- The prose scanner reports zero hard findings on every touched entrypoint and reference at the agent surface.
- The coordinator read each rewritten entrypoint against its keep list; the keep lists and the per-skill worker reports are summarized in the pull request.
- A Codex review of the combined diff returned NEEDS_CHANGES with five dropped safeguards and six consistency findings; all were fixed before merge and a second pass confirmed closure; the dispositions are recorded in the pull request.

Not established: whether compression changes task outcomes. As in September, reduction is a maintenance result, not evidence of better agent accuracy. The next useful measurement remains a small set of repeatable real tasks run with and without the changed skills under the same model and harness.

The installed-state findings (six symlinks to retired skills and one superseded third-party skill in a user's shared skills directory) concern one machine, not this repository; the plugin and `npx skills add` paths were unaffected.
